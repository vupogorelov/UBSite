# Развёртывание

## Первый запуск (или после обновления до версии с учётными записями)

```sh
npm install          # только при первой установке
npm run build        # собрать интерфейс в web/dist
npm start            # сервер на http://127.0.0.1:4300; миграции базы применяются сами
npm run admin -- init <имя>   # один раз: первый администратор; печатает ссылку для пароля
```

`init` передаёт администратору всё, что было создано до появления учётных записей:
пространство «Личное», заметки, историю поиска; оформление становится его личными настройками.

Другие команды (работают и при запущенном сервере):

| Команда | Что делает |
|---|---|
| `npm run admin -- reset <имя>` | ссылка для нового пароля (если администратор забыл свой) |
| `npm run admin -- invite` | ссылка для новой учётной записи (`--admin` — администратора) |

Остальное — в интерфейсе: меню пользователя → «Рабочие пространства» / «Администрирование».

## Доступ из интернета через HTTPS

Node слушает только `127.0.0.1`. Снаружи принимает соединения [Caddy](https://caddyserver.com) —
один исполняемый файл, сам получает и продлевает сертификат Let's Encrypt.

Всё нужное лежит в папке `deploy/`: `caddy.exe` (v2.11.6, с caddyserver.com), `Caddyfile`, `start.ps1`,
`setup-admin.ps1`. Сертификаты Caddy хранит в `deploy/caddy-data`, журнал запросов — в `deploy/logs`.

1. **Роутер:** пробросить TCP **80 и 443** на этот компьютер (`192.168.3.2`; лучше закрепить адрес за ним в DHCP).
   Внешний (WAN) адрес роутера должен совпадать с адресом домена (`95.31.142.59`). Если на роутере адрес вида
   `10.x`, `100.64–127.x`, `172.16–31.x` или `192.168.x` — у провайдера CGNAT, и проброс не поможет.
2. **VPN:** исключить из туннеля `deploy\caddy.exe` (раздельное туннелирование): соединения из интернета принимает
   Caddy, и его ответы должны уходить через провайдера, а не через VPN. Node трогать не нужно — он слушает только 127.0.0.1.
3. **Один раз от администратора:** `powershell -ExecutionPolicy Bypass -File deploy\setup-admin.ps1` — правила
   брандмауэра для `caddy.exe` (80/443) и автозапуск при входе в Windows.
4. **Запуск:** остановить сервер, запущенный через `npm start`, и выполнить `powershell -ExecutionPolicy Bypass -File deploy\start.ps1`
   (дальше он будет запускаться сам). Скрипт поднимает сервер с `UB_PUBLIC_URL` (ссылки-приглашения ведут наружу) и Caddy.
   При первом запуске Caddy получит сертификат — нужен открытый порт 80.
5. **Проверка:** открыть `https://95-31-142-59.broadband.corbina.ru` с телефона через мобильный интернет (не через домашний Wi-Fi).

Ссылки-приглашения из консоли создавать с тем же адресом: `$env:UB_PUBLIC_URL = 'https://95-31-142-59.broadband.corbina.ru'; npm run admin -- invite`.

Адрес провайдера может смениться (динамический IP) — тогда домен перестанет вести к вам; надёжнее завести
бесплатный DDNS-поддомен (например, duckdns.org) и указать его в `Caddyfile` и `start.ps1`.

Если Let's Encrypt откажет для домена провайдера (лимит выпуска считается на весь `corbina.ru`),
подойдёт бесплатный DDNS-поддомен (например, duckdns.org), указывающий на тот же IP: заменить имя в `Caddyfile`
и в `UB_PUBLIC_URL`.

## Перезапуск

```powershell
powershell -ExecutionPolicy Bypass -File deploy\restart.ps1          # перезапустить сервер и Caddy
powershell -ExecutionPolicy Bypass -File deploy\restart.ps1 -Build   # сначала пересобрать интерфейс (после обновления кода)
```

Скрипт останавливает только процессы платформы (Node на порту 4300 вместе с его окном и `deploy\caddy.exe`),
запускает `start.ps1` и проверяет, что сервер отвечает, а Caddy слушает 443. Если сборка с `-Build` не удалась,
перезапуска не будет — продолжит работать прежняя версия.

## Автозапуск в Windows

`deploy\setup-admin.ps1` регистрирует задачу «Urantian Docs Explorer» в Планировщике: при входе пользователя
она запускает `deploy\start.ps1`. Убрать: Планировщик заданий → удалить задачу.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `UB_PORT` | `4300` | порт сервера |
| `UB_HOST` | `127.0.0.1` | адрес; не меняйте при работе через Caddy |
| `UB_DB` | `data/ub.db` | файл базы |
| `UB_PUBLIC_URL` | — | внешний адрес для ссылок-приглашений |
| `UB_SECURE_COOKIES` | — | `1` — всегда ставить cookie с флагом Secure (Caddy и так сообщает о HTTPS) |
| `UB_BACKUPS` / `UB_BACKUPS_KEEP` | вкл. / `14` | ежедневная копия базы в `data/backups/` и сколько копий хранить |
| `UB_SEARCH_TIMEOUT_MS` | `3000` | предел времени одного поискового запроса |

## Резервные копии

Раз в сутки сервер делает согласованную копию базы в `data/backups/ub-ГГГГ-ММ-ДД.db` (последние 14).
Восстановление: остановить сервер, заменить `data/ub.db` копией, удалить `data/ub.db-wal` и `data/ub.db-shm`, запустить.
Копии стоит время от времени уносить на другой диск.
